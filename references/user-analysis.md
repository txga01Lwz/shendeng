# 用户研究与商业洞察工作流（user-analysis）

> 适用：用户研究、产品/文案/品牌/销售等商业场景。当 SKILL 识别到「用户分析 / 商业洞察」任务时加载本文件。
> 出处：听心格爱 · 东方心理学 · 罗伟泽

## 核心原则

- 用户的「心」是**假设**，不是事实。绝不从「不买 / 不用 / 流失」直接断言「怕被骗、怕麻烦、怕不被爱」。
- 区分四类证据：用户原话 / 行为数据 / 访谈观察 / AI 猜测，四者不可混为一谈。
- 商业洞察是「看见用户」的工具，**不替代**用户研究、数据分析、可用性测试、业务验证。

## 用户洞察卡（每次分析先走这张卡）

| 字段 | 要回答的问题 |
|---|---|
| 目标人群/场景 | 谁，在什么时刻、任务或约束下？ |
| 用户证据 | 用户原话、行为数据、访谈观察分别是什么？来源和样本清楚吗？ |
| 明确需求 | 用户直接说想完成什么，当前怎么完成？ |
| 心理假设 | 哪些可能的担心、期待、保护、价值判断？**标记为假设，不当事实** |
| 替代解释 | 价格、功能、易用性、时机、信任、权限、资源、竞品能否解释行为？ |
| 验证动作 | 访谈问题、可用性测试、行为数据、小实验；**不诱导答案** |
| 设计/表达响应 | 如何让用户更容易理解、选择、完成任务？明确真实限制与成本 |
| 指标与伦理 | 用户成功/满意/投诉/退订等；**不得用恐惧、羞耻、脆弱、虚假稀缺驱动转化** |

## 常见错误与正确做法

**错误（强推断）**：用户说「太贵」→ 直接认定「怕买错」→ 写逼单话术。

**正确（先澄清）**：用户说「太贵」→ 列为多种可能（预算 / 价值 / 风险 / 时机 / 方案不匹配）→ 先问对方关注的是哪一点，再做价值沟通。

## 伦理红线

- 不得利用恐惧、羞耻、脆弱、虚假稀缺、焦虑驱动转化。
- 尊重拒绝：用户/客户说「不」，不继续施压、不操纵。
- 商业文案可以「让用户感到被理解」，但不得「操纵用户服从」。
